```csv

```

CSV formatting requirements:

- Use commas between the five fields and one record per question.

- Inside a quoted field, replace each double quote with two double quotes. Backslashes are not CSV quote escapes.
- Preserve ordinary LaTeX backslashes exactly; do not double them merely because the content is CSV.

For example, this HTML:

```html

```

must have its attribute quotes doubled when it appears inside a quoted CSV field:


## 3. question_html: the full question

Write a complete, self-contained question that assesses the requested skill at the selected grade and difficulty.

- Do not reveal the answer in the question, an image caption, or image alternative text.
- Avoid references to unavailable worksheets, earlier questions, or images that are not in the package.
- Use HTML rather than Markdown for emphasis, lists, tables, and mathematical content.

- Include the tags metadata comment described in section 7 once per generated question.

Example of suitable question HTML before CSV escaping:

## 4. Mathematics and CKEditor-compatible MathJax

EOG Prep uses CKEditor with MathJax. Use formatted mathematics where it improves readability, particularly for fractions, powers, roots, equations, inequalities, coordinates, and geometry formulas.

Use this inline format:

```html
<span class="math-tex">\( ... \)</span>
```

Examples before CSV escaping:

```html
<p>Simplify <span class="math-tex">\(\frac{18}{24}\)</span>.</p>
<p>Solve <span class="math-tex">\(3x + 5 = 20\)</span>.</p>
<p>Calculate <span class="math-tex">\(4^2 + \sqrt{9}\)</span>.</p>
```

For a separate display equation, the importer also accepts:

```html
<div class="math-tex">\[A = \frac{1}{2}bh\]</div>
```

MathJax rules:

- Keep explanatory prose outside the math wrapper.
- Use valid LaTeX, including \frac{a}{b}, \sqrt{n}, x^2, \times, and \div where appropriate.
- Keep the opening and closing math delimiters paired.
- Preserve LaTeX backslashes in the final CSV.
- Do not use $...$ or $$...$$ delimiters, MathML, script tags, or external MathJax imports.
- Do not wrap simple standalone numbers in MathJax unless formatting is useful.
- The same math wrappers may be used in question_html, solution_html, and MCQ choices.
- Text-entry answers must remain plain text, without HTML or MathJax wrappers.
- The pipe character is reserved for answer separators. Inside a mathematical MCQ choice, use LaTeX \vert rather than a literal | when you mean an absolute-value bar.

Allowed HTML elements are:
p, br, span, div, strong, em, b, i, u, s, sub, sup, ul, ol, li, table, thead, tbody, tfoot, tr, td, th, caption, blockquote, img, h2, h3, h4.

Use only simple formatting. The only supported class is math-tex on span or div. Images may use src, alt, title, and optional positive integer width/height. Table cells may use positive integer colspan/rowspan. Numeric attribute values must be 1–9999. Do not add inline styles, other classes, id attributes, event handlers, hyperlinks, scripts, iframes, SVG markup, or embedded objects. Prefer paragraphs and inline MathJax over elaborate layouts.

## 5. question_type and answer

question_type must be exactly one of these lowercase values:

```text
text
mcq
```

### Text-entry questions

For question_type=text, answer contains a plain-text accepted answer:

```text
12
```

Separate genuinely equivalent accepted alternatives with two consecutive pipes:

```text
12||twelve
```

Another example, when all three forms are appropriate for the question:

```text
0.5||1/2||one half
```

Text-answer rules:

- Supply at least one nonempty answer.
- Use || only to separate acceptable alternatives, not solution steps or separate parts of a question.
- Do not add a correct-answer asterisk to text answers.
- Do not use HTML, MathJax, Markdown, or explanatory sentences in the answer field.
- If the question requires a particular form, such as a simplified fraction, only list answers that satisfy that instruction.
- Specify units or rounding in the question and make the accepted answers consistent with those requirements.
- Avoid questions requiring an essay, diagram drawing, or several independently marked responses; the importer stores a single answer entry with optional alternatives.
- Do not include empty or duplicate alternatives, and do not include a literal single pipe within an alternative.

### Multiple-choice questions

For question_type=mcq, put the choices in answer separated by single pipes. Place exactly one * immediately before the correct choice:

```text
9|12|*18|24
```

Choices can use simple HTML. When using paragraphs:

```html
<p>9</p>|<p>12</p>|*<p>18</p>|<p>24</p>
```

Choices can also contain CKEditor-compatible mathematics:

```html
<p><span class="math-tex">\(\frac{1}{3}\)</span></p>|*<p><span class="math-tex">\(\frac{1}{2}\)</span></p>|<p><span class="math-tex">\(\frac{2}{3}\)</span></p>
```

MCQ rules:

- Use four choices by default, unless my requirements call for another count. The importer accepts 2–20 choices.
- Exactly one choice must begin with *. Keep the marker outside its HTML, immediately before the choice.
- Every choice must be nonempty and distinct, with exactly one mathematically correct answer.
- Choose plausible distractors based on likely misunderstandings. Avoid choices that are equivalent to the correct answer in a different form.
- Shuffle the choices independently for each question after solving it.
- Spread correct choices reasonably across the available positions. Do not always put the answer first or follow a repeating position pattern.
- After shuffling, check the mathematics again and keep * attached to the correct choice.
- Do not add A/B/C/D labels or refer to an answer by a letter in the solution; the option's content should stand on its own.
- Do not use || between MCQ choices, trailing separators, literal pipes inside a choice, or images inside choices.
- The importer preserves the supplied order. You must perform the shuffling before packaging the questions.

For both types, the importer accepts at most 20 alternatives/choices and at most 1,000 UTF-8 bytes per individual answer/choice, including any MCQ HTML.

## 6. solution_html: a worked explanation for every question

Every question needs a complete, nonempty solution_html field.

- Explain the reasoning and calculation that lead to the answer; do not only state the answer again.
- Match the explanation to the selected grade and difficulty.
- Give each written step or paragraph its own <p>...</p> element.
- Use the MathJax formatting from section 4 for expressions that benefit from it.
- Show enough intermediate work for a student to follow the method.
- State the final answer clearly, including required units or rounding.
- Make sure the final result agrees with the accepted text answer or the starred MCQ choice.
- For an MCQ, explain why the correct choice works. Mention a common error only when it is useful.
- Refer to features of a diagram accurately. If an additional explanation image is necessary, package and list it under the same image rules as a question image.
- Do not use Markdown headings, Markdown bullets, code fences, external image URLs, or local computer paths inside the field.

Example before CSV escaping:

```html
<p>Use the order of operations: multiply before adding.</p>
<p>First calculate <span class="math-tex">\(3 \times 4 = 12\)</span>.</p>
<p>Then calculate <span class="math-tex">\(5 + 12 = 17\)</span>.</p>
<p>The answer is 17.</p>
```

## 7. Tags inside question_html

EOG Prep keeps exactly five CSV columns, so write tags in one HTML comment within question_html:

```html
<p>Simplify the fraction.</p>
<p><span class="math-tex">\(\frac{6}{8}\)</span></p>
<!-- tags: fractions|simplifying-fractions -->
```

The importer saves those tags separately and removes the comment from the displayed question. The importer permits tags to be omitted, but for packages you generate, include 1–5 relevant tags per question unless I request otherwise.

Tag-writing guidelines:

- Separate tags with a single | inside the comment.
- Use one tags comment per question, with no empty entries or duplicates.
- Prefer concise lowercase terms describing the assessed skill or problem type.
- Use hyphens for multiword terms, such as equivalent-fractions, number-lines, or word-problems.
- Keep spelling consistent across the package. Choose one term for a concept instead of several near-identical variants.
- Avoid vague labels such as maths, question, easy, or hard; topic and difficulty are already selected separately.
- Do not put the tags comment in solution_html or answer.
- Do not create a separate tags CSV column.

Storage limits: at most 20 tags, at most 60 characters per tag, and at most 1,000 UTF-8 bytes for all tags including separators. Tags must be nonempty plain text, without HTML or control characters.

Examples of the metadata comment:

```html
<!-- tags: addition -->
<!-- tags: fractions|equivalent-fractions|visual-fractions -->
<!-- tags: percentages|finding-a-percentage|word-problems -->
<!-- tags: patterns|sequences|missing-number -->
```

These are alternatives showing the format; use only one such comment within any individual question_html field.
